2026 - COMPUTER VISION

산업현장 PPE 탐지

산업현장 이미지에서 안전모와 안전조끼 착용 여부를 탐지하는 YOLO 기반 시스템

GitHub

1현장 안전 문제 정의

문제 배경

  • 안전모와 안전조끼 착용 여부는 반복 확인이 필요하지만 육안 점검은 누락 가능성이 있음
  • CCTV가 있어도 미착용 상태를 자동 판별하지 못하면 사후 확인에 그칠 수 있음
  • 작업자 단위로 보호구 미착용 상태를 정리하는 탐지 흐름이 필요

탐지 클래스

  • Hardhat, NO-Hardhat, Safety Vest, NO-Safety Vest, Person 5개 클래스로 구성

2YOLO 추론과 후처리 설계

구현 방식

  • YOLO 모델로 Person, Hardhat, NO-Hardhat, Safety Vest, NO-Safety Vest 감지
  • 사람 박스 기준으로 헬멧은 상단, 조끼는 몸통 영역의 박스만 상태 후보로 사용
  • 착용/미착용 박스가 겹치면 confidence를 비교해 상태를 정리
  • 조끼 착용 박스는 신뢰도가 낮을 때 색상 기준을 보조로 활용해 오탐을 완화
핵심 역할

모델 결과를 그대로 보여주지 않고, 안전관리자가 판단하기 쉬운 작업자별 상태로 재구성

  • Person 박스 기준으로 보호구 탐지 결과를 작업자별 상태로 묶는 후처리 설계
  • 헬멧은 상단, 조끼는 몸통 영역 중심으로 판단해 오탐을 줄이는 규칙 적용
  • 이미지-영상-웹캠 입력에서 같은 방식으로 결과를 확인하도록 UI 구성

3시연 기능과 한계 분석

구현 기능

  • 사진-동영상 업로드와 OpenCV 기반 로컬 웹캠 입력 지원
  • 동영상과 웹캠에서는 ByteTrack으로 작업자 ID와 최근 상태 유지
  • Gradio UI에서 탐지 결과 이미지와 작업자별 안전장비 상태 표 확인

한계 및 개선 방향

  • 마스크, 일반 점퍼, 원거리 헬멧 등 애매한 객체는 오탐 가능성이 존재
  • 미착용 기록 저장, 알림, 관리자 대시보드, CCTV 연동은 향후 확장 과제

Stack

PythonUltralytics YOLOOpenCVByteTrackGradio

Detection Flow

  1. 이미지, 영상, 웹캠 프레임을 입력으로 YOLO 추론 수행
  2. Person, Hardhat, NO-Hardhat, Safety Vest, NO-Safety Vest 감지
  3. ByteTrack과 후처리 규칙으로 작업자별 착용 상태 정리

Field Point

산업현장 적용 시 실시간 알림, 미착용 이력 저장, CCTV 연동까지 확장 가능

2026 - AI AGENT

구독 관리 에이전트

Discord 봇과 Streamlit 대시보드로 구독 정보를 한곳에서 관리하는 AI 서비스

GitHub

1문제 정의와 서비스 목표

문제 배경

  • OTT, 배달 멤버십, AI 서비스 등 월 구독이 늘어나며 갱신일과 총 지출 파악이 어려움
  • 기존 가계부 방식은 정해진 양식에 맞춰 입력해야 해서 지속 사용성이 낮음
  • 등록부터 조회, 요약, 지출 분석까지 이어지는 간단한 관리 흐름이 필요

서비스 목표

  • Discord 채팅으로 구독을 등록하고 금액-주기-결제일을 구조화해 저장
  • 대시보드에서 월-연 비용, 갱신 임박 항목, 카테고리별 지출을 확인

2AI 입력 처리와 백엔드 구조

구현 방식

  • “넷플릭스 월 15000원 등록해줘” 같은 문장에서 서비스명, 금액, 결제주기를 추출
  • FastAPI 백엔드가 Discord Bot, SQLite, OpenAI API, Streamlit을 연결
  • 대화 흐름, 정규화, LLM 처리, intent handler를 분리해 확장하기 쉬운 구조로 설계

핵심 기능

  • 구독 추가-수정-해지, 목록 조회, 월 예상 지출 요약, 비싼 구독 TOP 3 제공
  • 서비스별 월 구독비, 카테고리별 비용, 갱신 임박 D-day 카드 구성
핵심 역할

비정형 채팅 입력을 서비스 데이터로 변환하고, 봇, API, 대시보드가 같은 데이터를 보도록 설계

  • 자연어 문장에서 서비스명, 금액, 결제주기, 날짜 정보를 추출하는 구조 정의
  • Discord Bot, FastAPI, SQLite, Streamlit이 동일한 구독 데이터를 공유하도록 연결
  • 조회-요약-수정 기능을 intent 단위로 분리해 확장하기 쉽게 구성

3배운 점과 확장 방향

배운 점

  • 생성형 AI를 단순한 답변 도구가 아닌 모호한 사용자의 입력을 구조화하는 인터페이스로 활용
  • 챗봇과 대시보드가 같은 백엔드를 공유하는 서비스 계층 구조를 이해

향후 개선

  • 사용자별 인증과 개인 DB를 분리해 실제 개인 구독 관리 서비스로 확장
  • 갱신 임박 알림과 결제 캘린더 연동으로 결제 전 확인 흐름 강화
  • 월 지출 패턴을 바탕으로 중복 구독, 고정비 증가, 절감 후보를 추천

Stack

PythonFastAPIOpenAI APIDiscord BotStreamlitSQLite

Service Flow

  1. 사용자가 Discord에 구독 정보를 자연어로 입력
  2. OpenAI API가 핵심 필드를 추출하고 FastAPI가 저장
  3. Streamlit 대시보드에서 월 지출, 갱신 임박, 카테고리 비용 확인
