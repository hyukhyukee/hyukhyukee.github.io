2026 - AI SAFETY SERVICE

SafeFit AI

A human-in-the-loop industrial safety service combining LLM context understanding with deterministic retrieval, validation and scoring.

GitHub

1Hybrid AI with separated LLM and rule-engine roles

Context analysis pipeline

  • Parsed natural-language work descriptions through the OpenAI Responses API using a Strict JSON Schema that accepts only approved task and risk tags.
  • Controlled model variability on the server with alias mapping, tag normalization, deduplication and deterministic fallbacks.
  • Logged tokens, cost, response time and status for every call, while caching repeated reports to track operational cost.

My design decisions

  • Assigned ambiguous language interpretation to the LLM and repeatable search, scoring and decisions to the rule engine.
  • Designed a human-in-the-loop flow in which AI supplies evidence and candidates while managers retain final approval.

2Question recommendation with rule ranking and LLM reranking

Initial question-set construction

  • Rewarded category priority, tag overlap and review status, while applying quality penalties to generic wording, short answers and duplicates.
  • Prevented topic imbalance by selecting a representative item for each task category before filling the remaining slots by score.
  • Alternated true/false answer patterns and reduced consecutive items with similar tags to improve set diversity.

Reason-aware replacement ranking

  • Combined category, tags, manager reason, item type, difficulty and review status, then penalized duplicate candidates.
  • Sent only the top 12 rule-ranked candidates to the LLM for relevance reranking and adjusted future scores with accepted and rejected tag history.

3Evidence-grounded retrieval and automated correction loop

Evidence-grounded RAG

  • Built search queries from item tags, manager-reported errors and recent rejection reasons to retrieve KOSHA accident cases and safety regulations.
  • Scored query, title and key-phrase matches, and revised an item only when both KOSHA and regulatory evidence were available.
  • Passed retrieved evidence into the prompt to reduce revisions that drift from source material.

Validation and approval loop

  • Automatically checked option count, answer presence, duplication, explanation length, tag consistency and evidence overlap, then retried up to twice with explicit error feedback.
  • Committed only manager-approved revisions to the question bank and stored rejection reasons in SQLite for reuse in later retrieval and recommendations.

4Explainable scoring and full-stack operations

Scoring and weak-area algorithm

  • Normalized up to 20 active scoring tags by frequency and priority, then aggregated item scores at tag level.
  • Calculated the final result as the arithmetic mean of visible tag scores so workers and managers share the same scoring basis.
  • Combined exposure count, incorrect-answer count and ratio, high-risk errors and tag averages to identify the five weakest tags.

Implementation scope

  • Built role-based React and TypeScript screens, FastAPI endpoints, SQLite state models and AI usage logging as a solo developer.
  • Connected the full workflow from work registration and question review to mobile testing, result analysis and manager decisions.

2026 - COMPUTER VISION

Industrial Site PPE Detection

A YOLO-based system that detects hardhat and safety-vest compliance in industrial-site images and video.

GitHub

1Defining the field-safety problem

Background

  • Hardhat and safety-vest checks are repetitive, while visual inspection can miss non-compliance.
  • CCTV alone supports only retrospective review unless PPE status is classified automatically.
  • The workflow needed to organize compliance results around each visible worker.

Detection classes

  • Configured five classes: Hardhat, NO-Hardhat, Safety Vest, NO-Safety Vest and Person.

2YOLO inference and post-processing

Implementation

  • Detected Person, Hardhat, NO-Hardhat, Safety Vest and NO-Safety Vest with YOLO.
  • Used only helmet boxes near the upper person region and vest boxes near the torso as valid status candidates.
  • Compared confidence values when compliance and non-compliance boxes overlapped.
  • Applied color-based cues as a secondary check for low-confidence vest detections.
Core contribution

Reorganized raw detections into person-level states that a safety manager can review.

  • Grouped PPE detections around each Person box.
  • Applied upper-body and torso rules to reduce false matches.
  • Kept one result format across image, video and webcam input.

3Demonstration features and limitations

Implemented features

  • Supported image and video uploads plus local webcam input through OpenCV.
  • Used ByteTrack in video and webcam modes to retain worker IDs and recent PPE state.
  • Displayed annotated output and a worker-level compliance table in Gradio.

Limitations and next steps

  • Masks, ordinary jackets and distant helmets can still produce ambiguous detections.
  • Event storage, alerts, a manager dashboard and CCTV integration remain expansion opportunities.

Detection Flow

  1. Run YOLO inference on images, video or webcam frames.
  2. Detect person and PPE compliance classes.
  3. Combine tracking and post-processing into worker-level states.

Field Point

2026 - AI AGENT

Subscription Management Agent

An AI service that manages subscription records through a Discord bot and Streamlit dashboard.

GitHub

1Problem definition and service goals

Background

  • As streaming, delivery memberships and AI services multiply, renewal dates and total monthly spending become difficult to track.
  • Traditional budget tools require rigid input formats, which reduces continued use.
  • A simpler flow was needed from registration and lookup to summaries and spending analysis.

Service goals

  • Register subscriptions through natural-language Discord messages and store normalized amount, cycle and billing-date fields.
  • Show monthly and annual cost, upcoming renewals and category spending on a dashboard.

2AI input processing and backend architecture

Implementation

  • Extracted service name, amount and billing cycle from requests such as “Register Netflix at KRW 15,000 per month.”
  • Connected Discord Bot, SQLite, OpenAI API and Streamlit through a FastAPI backend.
  • Separated conversation state, normalization, LLM processing and intent handlers for extensibility.

Core features

  • Supported add, update, cancel and list operations, plus expected monthly spending and the three most expensive subscriptions.
  • Built monthly-cost, category-cost, and renewal D-day views.
Core contribution

Converted unstructured messages into service records shared by the bot, API and dashboard.

  • Defined normalized fields for service, amount, billing cycle and date.
  • Connected all interfaces to the same subscription data.
  • Separated lookup, summary and update operations into intent-level handlers.

3Lessons learned and expansion path

Lessons learned

  • Used generative AI as an interface for structuring ambiguous user input, not only as a response generator.
  • Learned how a chatbot and dashboard can share one backend service layer.

Next improvements

  • Separate authentication and personal databases for a production subscription service.
  • Add renewal notifications and calendar integration for pre-payment review.
  • Recommend duplicate subscriptions, fixed-cost increases and savings opportunities from spending patterns.

Stack

PythonFastAPIOpenAI APIDiscord BotStreamlitSQLite

Service Flow

  1. Enter subscription information in natural language through Discord.
  2. Extract core fields with the OpenAI API and store them through FastAPI.
  3. Review spending, renewals and category costs in Streamlit.
